## 2024-05-24 - [Implement HTTP Batch Query API]
**Learning:** Adding endpoints in a clustered environment requires forwarding cluster writes to the leader securely. Because tests may not run under full async web contexts out-of-the-box (e.g. absent `axum-test` extensions for `tower::ServiceExt` like `oneshot`), keeping core logic testable without HTTP wrappers is a priority.
**Action:** When adding HTTP APIs that modify state, always handle routing them explicitly to the cluster leader, and implement core logic testing via directly executing against `GraphGuard` sequentially or in an abstracted layer to bypass complex network mocking.
## 2026-09-19 - [Axum Middleware Compilation Issue]
**Learning:** In yagdb's Axum 0.6 setup, adding `tower_http::decompression::RequestDecompressionLayer` directly via `.layer()` causes an `Infallible: From<Box<dyn Error>>` trait bound error if wrapped with a `HandleErrorLayer` that has a `tower::BoxError` input, because Axum's inner routing service has an error type of `Infallible`. `RequestDecompressionLayer` should be used directly without a `HandleErrorLayer` as the decompression error handling is managed asynchronously by the request body stream and directly mapped to bad requests natively by tower.
**Action:** When adding standard `tower-http` middleware to Axum routers, ensure its expected error output exactly matches the wrapped service type, and avoid wrapping natively infallible stream services in explicit `HandleErrorLayer`s.
